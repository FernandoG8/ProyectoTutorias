1. MÉTODO APLICADO

MÉTODO SELECCIONADO: SANDWICH (Integración Híbrida) + INTEGRACIÓN CONTINUA

JUSTIFICACIÓN:
──────────────

El proyecto implementa Clean Architecture con tres capas bien definidas:
  ✓ Domain Layer (Entidades, reglas de negocio)
  ✓ Application Layer (Servicios, DTOs, casos de uso)
  ✓ Infrastructure Layer (Controladores, configuración, acceso a datos)

El método Sandwich fue elegido por:

1. INDEPENDENCIA DE CAPAS
   • Domain: Testing Bottom-Up (validar entidades aisladas)
   • Application: Testing híbrido (servicios con mocks)
   • Infrastructure: Testing Top-Down (controladores integrados)

2. FLEXIBILIDAD
   • Permite testing de cada capa según su naturaleza
   • No bloquea entre dependencias (paralelizable)
   • Combina tests automatizados + validación manual

3. RIESGOS DISTRIBUIDOS
   • No concentra en una sola capa
   • Valida integración progresiva entre capas
   • Facilita detección de problemas específicos

4. ESCALABILIDAD
   • Fácil agregar tests sin refactorizar existentes
   • Soporta crecimiento incremental
   • Compatible con CI/CD
